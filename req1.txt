2. About email verification

For this part, you're actually very close. You do not need to build an email server yourself.

Your architecture should look like this:

User
  │
  │ Sign Up
  ▼
Django
  │
  │ Create account
  │ is_verified = False
  ▼
Generate verification token
  │
  ▼
Email service
  │
  │ sends email
  ▼
User's Gmail / Outlook / etc.
  │
  │ clicks "Verify Email"
  ▼
Django verification URL
  │
  ▼
Verify token
  │
  ▼
is_verified = True
  │
  ▼
Account activated

Django itself already has an email-sending system through django.core.mail, including SMTP support.

What Django doesn't provide by itself is the actual email delivery infrastructure you want for production. That's where something like Resend or Brevo comes in.

3. What I'd recommend for MedSync

For your project, I'd start with Resend.

Resend

It's an email delivery service designed for applications. It supports SMTP, so Django can communicate with it using its normal email backend. Resend documents Django/SMTP integration and provides SMTP credentials.

Your stack becomes:

MedSync
│
├── Frontend
│
├── Django
│   ├── Authentication
│   ├── Doctors
│   ├── Patients
│   ├── Appointments
│   └── Email Verification
│
├── PostgreSQL
│
└── Resend
     └── Transactional Email

You could also use Brevo. It supports transactional email through SMTP and explicitly supports messages such as account creation and password resets.

Brevo

I'd personally use Resend for this project because you mainly need transactional emails, not a giant marketing-email platform.

4. Don't use your personal Gmail as the production mail server

You can configure Django with an SMTP provider during development, but I wouldn't build MedSync's production email system around your personal Gmail account.

Instead:

MedSync
   ↓
Django
   ↓
Resend
   ↓
user@gmail.com

Later, once you have your own domain, you can have something like:

MedSync
   ↓
Django
   ↓
Resend
   ↓
no-reply@medsync.com

You'll also want to authenticate your domain with the email provider for better deliverability. Brevo, for example, explicitly recommends authenticating the sending domain.
